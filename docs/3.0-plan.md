# 3.0 Plan: Removing `HijrahDate` from Public API

## Goal

Remove all references to the alpha library `com.abdulrahman-b.hijrahdatetime` (`HijrahDate`, `HijrahYearMonth`) from the published public API. These types are deprecated in 2.x with owned replacements (`HijriDate`, `HijriYearMonth`).

## Affected Declarations

### `CalendarDay`
- **Constructor parameter** `hijrahDate: HijrahDate?` — Replace with `hijri: HijriDate?`
- **Property** `hijrahDate: HijrahDate?` (deprecated) — Remove entirely
- **`component1(): HijrahDate?`** — Change to `HijriDate?`
- **`copy()` signature** — Update first parameter type

### `CalendarMonth`
- **Constructor parameter** `hijriYearMonth: HijrahYearMonth` — Replace with `hijriYearMonth: HijriYearMonth`
- **Property** `firstDay: HijrahDate` — Change to `HijriDate`
- **Property** `hijriYearMonth: HijrahYearMonth` (deprecated) — Remove or change type

### `HijriCalendarState`
- **Constructor parameters** using `HijrahDate` — Replace with `HijriDate`
- **`selectDate(HijrahDate)`** — Replace with `selectDate(HijriDate)`
- **`goToMonth(HijrahYearMonth)`** — Replace with `goToMonth(HijriYearMonth)`
- **Secondary constructor** (deprecated) — Remove

### Extension Functions
- **`toCalendarMonth(HijrahYearMonth)`** — Replace with `HijriYearMonth` overload
- **`calendarMonthFor(HijrahYearMonth)`** — Replace with `HijriYearMonth` overload
- **`gregorianRangeFor(HijrahYearMonth)`** — Replace with `HijriYearMonth` overload

### Bridge Functions (internal, keep)
- `HijriDate.toHijrahDate()` — Keep internal for Pakistan math
- `HijrahDate.toHijriDate()` — Keep internal for Pakistan math

## Migration Path

### Before (2.x)
```kotlin
val day = CalendarDay(hijrahDate = someHijrahDate, ...)
val month = CalendarMonth(hijriYearMonth = someHijrahYearMonth, ...)
state.selectDate(someHijrahDate)
```

### After (3.0)
```kotlin
val day = CalendarDay(hijri = someHijriDate, ...)
val month = CalendarMonth(hijriYearMonth = someHijriYearMonth, ...)
state.selectDate(someHijriDate)
```

## Removal Order

1. Remove deprecated `CalendarDay.hijrahDate` property
2. Change `CalendarDay` constructor and component types
3. Remove deprecated `CalendarMonth.hijriYearMonth` property (if separate from owned type)
4. Change `CalendarMonth` constructor and property types
5. Update `HijriCalendarState` constructors and methods
6. Remove deprecated extension function overloads
7. Clean up internal bridge functions (keep only what Pakistan math needs)

## Shipping Conditions

- No open PRs depending on deprecated `HijrahDate` paths
- All tests pass with `HijriDate`/`HijriYearMonth` only
- `apiDump` shows no `com.abdulrahman_b.hijrahdatetime` references in public API
- CHANGELOG.md documents the breaking changes clearly
